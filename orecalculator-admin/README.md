# ローカルマスター管理

共通マスターは公開読み取りです。管理画面へのアクセスは `127.0.0.1` に限定し、通常サイトのビルドには含めません。

1. Supabase の SQL Editor でSQLを確認して適用します。新規DBには `orecalculator/supabase/master_data.sql`、旧マスターを作成済みの場合は `orecalculator/supabase/master_data_migrate_cost_reels.sql` を実行します。既存のユーザーデータ表には触れません。
2. PowerShell で、接続先と管理用キーをそのシェルの環境変数に設定します。
   ```powershell
   $env:ORE_ADMIN_SUPABASE_URL = 'https://<project>.supabase.co'
   $env:ORE_ADMIN_SUPABASE_SERVICE_KEY = '<service-role-key>'
   npm --prefix .\orecalculator run admin
   ```
3. `http://127.0.0.1:4174` を開きます。ポートを変える場合は `ORE_ADMIN_PORT` を設定します。終了は Ctrl+C です。

管理用キーはソースや公開ビルドに含めないでください。キーは管理者権限を持つため、第三者と共有しないでください。管理サーバーは実行している端末のローカルユーザーから利用可能です。

技の標準コストは技マスターで設定し、モンスター別・リール別の上書きは任意です。移行前に存在した技の標準コストは未設定になるため、管理画面で設定してください。既存モンスターのコストは上書き値として維持されます。

過去に標準コスト用のSQLを適用済みの場合は、`orecalculator/supabase/master_data_allow_negative_cost.sql` も実行すると負のコストを保存できます。モンスターの編集画面から複製して新規作成できます。複製は保存するまでDBに追加されず、進化ルールは引き継ぎません。

既存DBには `orecalculator/supabase/master_data_skill_defaults.sql` も適用してください。既存の技は変更せず、共通の発生リールとリール別コストを追加します。技の編集画面で設定でき、ためる（★1～3: 1、1.4、1.8）と上昇★移動（発生★1～3: 3、4、5）の入力補助も利用できます。既に入力された値は上書きしません。適用後、管理画面を再読み込みしてください。

発生リールのモンスター別設定が空欄の場合は技の共通設定を使います。コストの優先順はモンスターのリール別、モンスター別、技のリール別、技の標準値です。空欄の上書き値は共通設定に追従します。保存できない場合、入力エラーやサーバーエラーは保存ボタン付近にも表示されます。

各リールのキャパシティは下限・上限とも空欄で未設定、同じ値で確定値です。固定配置は各リールに1種類で、未設定枠は空欄のまま保存できます。引き継ぎありの進化は追加される最高リール、引き継ぎなしの進化は全リールを参照する想定です。旧形式の固定配置に相反する値がある場合、移行は停止するのでデータを確認してください。

通常アプリの「進化」では進化元・ルールを選び、進化後の個体を別に作成できます。引き継ぎありの場合は進化前の最高リールで置換する1枠と置換技を手動で選び、ほかの枠は技の対応を適用して引き継ぎます。クラスが1増える進化に対応し、新しい最高リールは進化先の固定配置を使います。引き継ぎなしの場合は全リールに進化先の固定配置を使います。キャパシティは進化先の範囲内で入力し、確定値は自動入力します。置換の抽選や進化を含むミス入れ経路の計算は未対応です。

通常アプリは固定配置と技をコピーして個体を作成します。キャパシティの範囲が未確定なら作成時に仮値を入力してください。個体は共通マスター更新に追従しません。既存の個体は進化元マスターを手動で選択します。個体の技IDがマスターと異なる場合は、その技に対応する進化元の技も選択します。
